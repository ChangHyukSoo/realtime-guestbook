# 구현 계획

## 진행 원칙

요구사항은 `prompt_draft.md`, 설계는 `architecture.md`, 실제 진행 결과는 `progress.md`를 기준으로 관리한다. 아래 항목은 아직 구현되지 않았다. 단계의 완료 기준을 충족한 뒤 체크하고, 외부 설정 때문에 검증하지 못한 항목은 미완료로 남긴다.

## 1. 프로젝트 기반 구성

- [ ] 기존 설정을 다시 확인하고 `ui_plan.png`의 화면 구성과 비율을 검토한다.
- [ ] Next.js + TypeScript + Tailwind CSS 앱을 초기화하고 개발·빌드·린트 명령을 마련한다.
- [ ] Supabase 클라이언트, 환경 변수 예시 파일, 공통 레이아웃과 세 화면의 라우트를 준비한다.
- [ ] 입력 제한 수치와 Storage 접근·저장 방식 등 설계의 미확정 사항을 결정해 기록한다.

완료 기준: 개발 서버에서 세 화면에 접근할 수 있고, 타입 검사 및 초기 빌드가 통과하며 비밀값이 저장소에 포함되지 않는다.

## 2. Supabase 데이터 기반

- [ ] 방명록과 댓글 테이블, 외래 키, 기본값, 검증 제약, 조회 인덱스를 SQL 마이그레이션으로 작성한다.
- [ ] 로그인 없는 읽기·등록에 필요한 RLS 및 권한을 작성한다.
- [ ] 이미지 버킷, MIME·크기 제한과 Storage 정책을 구성한다.
- [ ] 두 테이블의 Realtime 발행 및 읽기 권한을 설정한다.
- [ ] 업로드 후 DB 저장 실패 시 고아 파일 처리 방법을 구현하거나 운영 절차로 명시한다.

완료 기준: 실제 Supabase에서 허용된 읽기·등록이 동작하고 잘못된 입력 및 허용하지 않은 수정·삭제가 차단된다. 설정을 적용하지 못하면 SQL 작성 완료와 실제 검증을 구분해 기록한다.

## 3. 방명록 작성 및 저장

- [ ] ‘전자 방명록’ 제목과 사진 첨부·지우기·등록 버튼을 구현한다.
- [ ] 마우스·터치 필기, 사진 합성, 전체 초기화, 이미지 내보내기를 구현한다.
- [ ] 모바일 터치, 화면 배율, 크기 변경에 따른 좌표와 내용 보존을 처리한다.
- [ ] 파일 형식·크기 검증과 빈 캔버스 등록 차단을 적용한다.
- [ ] Storage 업로드 및 방명록 저장을 연결하고 성공 후 목록으로 이동한다.
- [ ] 저장 중 중복 제출을 막고 실패 시 작성 내용을 유지한다.

완료 기준: 데스크톱·모바일에서 사진 위에 필기한 결과가 저장되며, 지우기·빈 입력·중복 제출·실패 후 재시도가 올바르게 동작한다.

## 4. 방명록 목록 및 실시간 반영

- [ ] 최신순 이미지 카드 그리드, 작성 버튼, 상세 이동을 구현한다.
- [ ] 로딩·빈 목록·조회 오류 상태를 제공한다.
- [ ] 초기 조회와 Realtime 이벤트를 ID 기준으로 병합해 누락과 중복을 방지한다.
- [ ] 구독 해제와 재연결 후 재조회를 처리한다.

완료 기준: 두 브라우저 중 하나에서 방명록을 등록하면 다른 브라우저에 새로고침 없이 한 번만 표시되며 최신순을 유지한다.

## 5. 상세 화면과 댓글

- [ ] 선택한 이미지, 댓글 작성자·내용·상대 시간, 목록 이동 버튼을 구현한다.
- [ ] 닉네임·댓글 입력 및 공백·길이 검증을 구현한다.
- [ ] 댓글 저장 중 중복 제출 방지와 실패 시 입력 보존을 적용한다.
- [ ] 해당 방명록 댓글만 실시간 반영하고 중복 제거·구독 해제를 처리한다.
- [ ] 상대 시간 갱신과 존재하지 않는 방명록·조회 오류를 처리한다.

완료 기준: 두 브라우저에서 같은 상세 화면을 열고 댓글의 실시간 반영을 확인한다. 다른 방명록 댓글이 섞이지 않고 화면 재진입 후에도 중복되지 않는다.

## 6. 통합 검증과 사용 안내

- [ ] 참고 이미지의 구성·비율, 여백·글꼴·버튼과 모바일 레이아웃을 점검한다.
- [ ] 빌드·타입 검사·린트와 핵심 데이터 흐름에 필요한 검증을 수행한다.
- [ ] 두 브라우저에서 방명록·댓글 등록, 재연결, 화면 이동, 중복 이벤트를 확인한다.
- [ ] 저장 실패·잘못된 이미지·과도한 입력·빈 데이터 상태를 확인한다.
- [ ] 환경 변수, 로컬 실행, SQL 적용, Storage·RLS·Realtime 설정을 README에 설명한다.
- [ ] 두 브라우저 수동 검증 절차와 외부 설정 때문에 확인하지 못한 내용을 기록한다.
- [ ] 최종 구현에 맞춰 모든 메모리 문서와 필요한 `AGENTS.md` 규칙을 갱신한다.

완료 기준: 실행·설정 절차를 따라 앱을 재현할 수 있고, 검증 결과와 남은 제약이 명확하며 문서와 실제 코드가 일치한다.
